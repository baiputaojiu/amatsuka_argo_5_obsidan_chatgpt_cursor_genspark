# OneDrive保存先レコメンダー

OneDrive業務フォルダの保存先候補を表示する、個人用Windowsデスクトップアプリです。

MVP 0のStep 6まで完了しています。設定・カタログ、ファイル選択、検索語編集、候補表示、Outlook MSGの読み取り、確定パスのコピー、Audit記録、Codex相談支援を1画面へ接続し、要件定義書§20の機能10件・安全性6件を確認済みです。

MVP 1でOffice文書とPDFの本文抽出を追加しています。詳細は「対応するファイル形式」を参照してください。

## 開発環境

- Windows
- Python 3.12
- Outlookデスクトップアプリ（MSG確認時だけ必要）

```powershell

```

## 設定

実装後の設定例は`settings.example.json`を参照する。実際の`settings.json`、`catalog.json`、`audit.jsonl`は次のリポジトリ外へ置く。

```text
%LOCALAPPDATA%\OneDriveDestinationRecommender\
```

`settings.json`はアプリから作成・変更しない。`catalog.json`は、設定された今年度・昨年度フォルダを読み取り専用で完全走査できた場合だけ、同じランタイム領域で原子的に置き換える。

`audit.jsonl`は、Step 5で候補選択・保存先未定・却下を確定したときだけ1行追記する。日常の候補判定はこのログを読み込まず、自動学習や自動ルール変更を行わない。

今年度・昨年度フォルダには、Windowsの大文字小文字差を含めて同一ではなく、互いに入れ子でないパスを指定する。

## 使い方

1. 初回またはフォルダ構成変更後に「フォルダ構成を更新」を押す
2. 「ファイルを選択」でMSG 1件またはMSG以外のファイルを選ぶ。ファイルを使わない場合は検索欄へ直接入力する
3. 検索欄の語を必要に応じて追加・修正し、候補一覧から保存先を選ぶ
4. 「選択パスを確定・コピー」または「保存先未定」を押し、コピーされたパスを保存ダイアログ等へ貼り付ける
5. 候補に納得できない場合は、画面の添付案内を確認して「Codex相談用プロンプトをコピー」を押す

MSGは1件ずつ選択する。MSG以外の複数ファイルは1案件として扱う。「手動検索に戻す」を押すと、現在のファイル選択を解除して手動検索だけの状態へ戻る。

候補の確定、保存先未定、却下では`audit.jsonl`へ1行追記する。アプリはファイル移動、保存、フォルダ作成を行わない。

## 対応するファイル形式

ファイル名は形式によらず主検索語になります。次の形式は中身も読み、そこから作った語を**補助検索語**として使います。補助検索語は候補の並び順にだけ影響し、候補を増やすことはありません。

| 形式 | 拡張子 | 読む範囲 |
|---|---|---|
| Excel | `.xlsx` `.xlsm` | シート名と文字列セル。数値セルは使わない |
| Word | `.docx` | 本文のテキスト |
| PowerPoint | `.pptx` | スライドのテキスト。ノートは読まない |
| PDF | `.pdf` | テキストレイヤーのみ |

読まないもの：

- 旧バイナリ形式の`.xls` `.doc` `.ppt`
- スキャンしただけでテキストレイヤーを持たないPDF。OCRは行わない
- 画像、CAD、`.msg`以外のメール形式

いずれもファイルは読み取り専用で開き、抽出したテキストをディスクへ書きません。`settings.json`、`catalog.json`、`audit.jsonl`にも残りません。

本文を読めなかった場合は、そのファイルはファイル名だけで扱い、処理を続けます。画面には`本文を利用：1/2件`のように、対象件数と読めた件数を表示します。`openpyxl`と`pypdf`を導入できない環境でも、アプリの起動、手動検索、MSG、ファイル名による判定はそのまま利用できます。

## データの扱い

- 実業務のMSG、メール本文、添付内容をGitへ保存しない
- OneDrive上のファイル・フォルダを変更しない
- Outlook COMはローカルMSGの読み取りだけに使う
- MSGを読めない場合も、手動検索と通常ファイルの処理は継続できる構成にする
- MSG本文、文書の抽出テキスト、検索語全文、Codex相談用プロンプトをAuditへ記録しない
- Office文書とPDFは読み取り専用で開き、抽出したテキストと添付実体をディスクへ書かない
- Codex相談用の案内とプロンプトはメモリ上だけで生成し、ユーザー操作なしに送信・コピー・保存しない

## Auditを使った改善相談

判定の改善を望む場合だけ、次の手順で行う。アプリがAuditを自動的に学習へ使うことはない。

1. `%LOCALAPPDATA%\OneDriveDestinationRecommender\audit.jsonl`から、手動で修正した案件または却下した案件を確認する
2. 該当する元MSGまたは元ファイルを自分で選ぶ
3. Auditログと対象ファイルをCodexへ添付し、原因分析と改善案を依頼する
4. 提案内容を確認する
5. 採用する場合だけ、改めて明示的にプログラム変更を依頼する

Auditには業務ファイル名と業務フォルダの絶対パスが含まれるため、公開リポジトリへ置かない。
