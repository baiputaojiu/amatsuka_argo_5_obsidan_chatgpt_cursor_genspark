# 実装計画：候補フォルダのExplorer表示

## 1. 文書情報

- 対象：OneDrive業務フォルダ向け「保存先レコメンダー」
- 位置付け：MVP 0運用開始後の小改修（MVP 1とは区別する）
- 作成日：2026-08-02
- 基準ブランチ：`ferch1_保存先レコメンダー修正`
- 初版コミット：`a119cd5`
- 状態：実装前・再レビュー待ち

この文書は実装方法の合意を得るための計画書であり、プログラム本体の変更完了を示すものではない。

---

## 2. 目的

候補一覧に表示された保存先フォルダを、確定前にExplorerで開いて内容を確認できるようにする。

現在の「パスをコピー → Explorerへ切り替え → 貼り付け → 開く」という4操作を、候補一覧からの1操作へ短縮する。Explorer表示はPreviewであり、保存先の確定とは扱わない。

---

## 3. 対象範囲

### 3.1 今回実装するもの

- 候補行のダブルクリックで候補フォルダをExplorerに表示する
- 候補一覧にフォーカスがある場合だけ、Enterキーでも表示できるようにする
- 候補パスが存在しない場合、フォルダ構成の更新を案内する
- Explorer起動に失敗しても、現在の入力状態を維持して利用を継続する
- Explorerを実起動しない自動テストを追加する

### 3.2 今回実装しないもの

- OutlookメールまたはローカルファイルのD&D入力
- フォルダやファイルの自動作成・保存・移動・削除
- 候補を開いたことのAudit記録
- 候補を開いた時点での保存先確定・コピー
- Explorer上の操作の自動化
- Explorerのウィンドウ・タブの使い方の制御
- 設定項目、設定画面、外部依存、ログファイルの追加

---

## 4. 操作仕様

| 操作 | 挙動 |
|---|---|
| 候補行をシングルクリック | 候補を選択するだけ |
| 候補行をダブルクリック | 候補フォルダそのものをExplorerで開く |
| 候補一覧にフォーカスがある状態でEnter | 選択中の候補フォルダをExplorerで開く |
| 「選択パスを確定・コピー」 | 従来どおりコピー、確定、Audit記録を行う |

シングルクリックは候補を選ぶ操作として残し、Previewと分離する。Enterは`root`ではなく`candidate_tree`だけへバインドし、検索欄でEnterを押してもExplorerを起動しない。

Explorerでは候補フォルダの親ではなく、候補フォルダそのものを開く。Explorerが新規ウィンドウ、既存ウィンドウ、新規タブのどれを使うかはWindowsの設定に従う。

候補一覧の近くに次を常設する。

> 候補をダブルクリックするとExplorerで確認できます。開くだけでは保存先は確定されません。

成功時はExplorerが前面に出るため、追加メッセージを表示せず、既存の「候補N件」を維持する。

失敗時だけ、既存の`operation_status_var`へ次のいずれかを表示する。

- 候補フォルダが見つかりません。フォルダ構成を更新してください。
- 候補フォルダをExplorerで開けませんでした。パスを確認して再度お試しください。

---

## 5. Previewと確定の分離

Explorer表示経路は`_finalize`、`record_decision`、`_copy_text`を呼ばない。

Explorerで候補を開いても、次は変更しない。

- `audit.jsonl`
- クリップボード
- 確定パス表示
- 検索語
- 入力ファイル
- 候補一覧と候補順
- 自動検索語だけで候補0件だったかの測定値

保存先の確定は、従来どおり「選択パスを確定・コピー」「保存先未定」「却下」のいずれかを人が押した場合だけ行う。

## 6. 実装方式

### 6.1 Explorer起動関数

追加ファイルを作らず、既存の`session.py`へ約12行の小関数を追加する。

```text
open_folder(path, launcher=None)
  1. Path(path).is_dir()で既存フォルダか確認
  2. 存在しなければFileNotFoundError
  3. launcher指定時はその関数を使用
  4. 未指定時だけos.startfileを使用
  5. 絶対パスを1回だけlauncherへ渡す
```

- シェル用のコマンド文字列を組み立てない
- 日本語、空白、括弧を含むパスを変更しない
- テストでは`launcher`へ偽物を渡し、実際のExplorerを起動しない
- Windows外のヘッドレステストでは必ず偽物を渡す
- 新しい例外型、外部依存、設定は追加しない

`session.py`の本来の責務は入力状態の管理だが、今回は新規モジュールと新規テストファイルを増やさないことを優先する。

### 6.2 GUIイベント

`app.py`の既存`candidate_tree`だけへ次を登録する。

- `<Double-1>`：クリック位置の候補行を選択して開く
- `<Return>`：現在選択中の候補を開く

ダブルクリック時は`Treeview.identify_row(event.y)`を使い、見出し、スクロールバー、空白部分では何もしない。行を特定した後は`selection_set(row)`を行い、既存の`_selected_candidate_path()`から`Candidate.absolute_path`を取得する。

画面に表示されたパス文字列を再解析しない。候補一覧が再描画された直後などに選択が無効なら、既存メソッドが返す`None`をそのまま扱い、Explorerを起動しない。

## 8. エラー時の扱い

- 未選択でEnterを押した場合は何もしない
- 見出し・空白部分のダブルクリックでは何もしない
- 候補フォルダが存在しない場合は、カタログを自動更新せず更新操作を案内する
- `os.startfile`が`OSError`を返した場合は、現在の入力・検索語・候補を維持する
- 失敗しても警告用の新しいログを作らず、既存の状態欄だけで案内する
- パスやOS例外の詳細をAuditへ記録しない

## 9. テスト計画

### 9.1 単体テスト3件

1. 日本語・空白・括弧を含む既存フォルダの絶対パスを、偽物の起動関数へ1回だけ渡す
2. 存在しないフォルダでは`FileNotFoundError`となり、起動関数を呼ばない
3. 起動関数の`OSError`を握りつぶさず、GUI側が案内できる形で返す

既存の`test_session.py`へ追加し、新しいテストファイルは作らない。

### 9.2 GUI結合テスト3項目

既存のGUI結合テスト1件の中へ、次を追記する。

1. ダブルクリック相当で正しい候補パスを1回開き、その前後でAudit行数、クリップボード、確定パス、検索語、候補一覧が変わらない
2. 候補一覧にフォーカスがある状態のEnterで、現在選択中の候補を開く
3. 見出し・空白部分・未選択では起動関数を呼ばない

非存在と`OSError`は単体テストで確認し、GUI結合テストでは重複させない。

### 9.3 回帰テスト

- 既存の単体テスト87件とWindows結合テスト3件を維持する
- Ruffのformat checkとlintを通す
- Explorerを実起動しないテストはWindows外でも実行可能にする

### 9.4 手動確認4項目

1. 手動検索で候補を表示し、ダブルクリックで候補フォルダの内容がExplorerに表示される
2. Tab移動で候補一覧へフォーカスでき、Enterでも同じ候補を表示できる
3. Preview前後で確定パス表示と本番Audit行数が変わらない
4. その後の「選択パスを確定・コピー」は従来どおり動作する

Explorer表示経路にはOneDriveへの書き込みコードが存在しないため、MVP 0で実施した全件フィンガープリント比較は繰り返さない。

## 10. 受け入れ条件5件

1. 候補行のダブルクリックで、その候補フォルダをExplorerで開ける
2. 候補一覧にフォーカスがある場合、選択中の候補をEnterキーで開ける
3. 見出し・空白部分・未選択では起動処理を呼ばない
4. 存在しない候補・Explorer起動失敗のいずれでも、案内を表示してアプリを継続できる
5. Explorer表示だけでは、Audit、クリップボード、確定パス、検索語、入力ファイル、候補一覧を変更しない

既存挙動、新規依存の不在、OneDrive非変更は、既存テスト、差分レビュー、書き込み経路の不在で確認し、この小改修固有の受け入れ条件として二重管理しない。

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| 候補を選ぶだけでExplorerが開く | シングルクリックとダブルクリックを分離する |
| 検索欄のEnterでも起動する | バインド先を`candidate_tree`だけにする |
| 古いカタログに削除済みパスが残る | 起動前に存在確認し、手動更新を案内する |
| 古い選択から誤った候補を開く | 既存の`iid`と候補インデックスの対応を再利用する |
| Previewが確定処理へ混入する | `_finalize`を呼ばず、前後の不変値をテストする |
| Windows外のテストで失敗する | 偽`launcher`を注入し、`os.startfile`を呼ばない |
