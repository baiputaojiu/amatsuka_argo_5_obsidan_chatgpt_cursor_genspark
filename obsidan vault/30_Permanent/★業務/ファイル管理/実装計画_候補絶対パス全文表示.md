## 2. 解決する問題

候補一覧の「絶対パス」列は幅480pxであり、長いパスは列内で切れる。横スクロールバーを右端まで動かしても、列幅を超えた文字は表示されないため、候補の保存先を画面上で確認しづらい。

初回改修では、候補を選択すると絶対パス全文を候補一覧の下へ折り返して表示する欄を追加した。しかし実利用で、元の絶対パス列と横スクロール範囲は480pxのままであり、当初の問題を直接解決していないことが確認された。

追加改修では、表示候補中の最長パスを実際のTreeviewフォントで測定し、絶対パス列をその幅まで拡張する。これにより、横スクロールバーでパス末尾まで到達できるようにする。

## 3. 採用する最小仕様

- 候補一覧の下に「選択中の絶対パス」表示を1つ追加する
- 候補行を選択すると、対応する`Candidate.absolute_path`を省略せず折り返して表示する
- 候補描画時に最長の`Candidate.absolute_path`を実フォントで測定し、絶対パス列を測定幅＋余白まで拡張する
- 絶対パス列を画面幅に合わせて縮めず、横スクロールで末尾まで移動できるようにする
- 候補未選択時は「候補を選択すると絶対パスを全文表示します。」と表示する
- マウス選択、キーボードによる行移動、ダブルクリックのいずれでも同じ表示を更新する
- 検索語、入力ファイル、カタログの変更で候補を再描画するときは、古いパス表示を初期案内へ戻す
- 既存の絶対パス列と横スクロールバーは残す

表示は確認用であり、選択だけでは次を行わない。

- 保存先の確定
- Explorerの起動
- Auditログへの追記
- クリップボードへのコピー
- 検索語、入力、候補順の変更

## 5. 実装方式

### 5.1 表示

`app.py`の候補領域へ`StringVar`と折り返し可能な`ttk.Label`を追加する。既存の候補件数表示とExplorer Preview案内の間に配置し、現在の候補領域内で完結させる。

候補描画時は、Treeviewの実フォントで表示候補の絶対パスを測定する。絶対パス列は最小480pxとし、最長の測定幅に左右余白24pxを加えた値が480pxを超える場合はその値へ拡張する。`stretch=False`として画面幅による縮小を防ぎ、既存の横スクロールバーをそのまま使う。

表示値にはTreeviewの表示文字列を再解析せず、既存の`_selected_candidate_path()`を使う。これにより、Previewと確定が参照するパスと同じ値を表示する。

### 5.2 選択変更

候補一覧の`<<TreeviewSelect>>`を新しいハンドラへバインドする。

```text
候補選択
  → _selected_candidate_path()
  → 選択中の絶対パス表示を更新
```

ダブルクリック処理は行を選択してからExplorer Previewを呼ぶ現行順序を維持する。イベント順序に依存して表示が遅れないよう、ダブルクリックで`selection_set()`した直後にも同じ表示更新処理を呼ぶ。

### 5.3 再描画

`_clear_candidates()`で選択中パス表示を初期案内へ戻し、絶対パス列を最小480pxへ戻す。その後、`_render_candidates()`が現在の候補に合わせて列幅を再計算し、候補一覧を作り直す。通常の再描画とカタログ不一致による直接クリアの双方で、古いパスと古い列幅を残さない。

## 7. 自動テスト5項目

既存のGUI結合テストへ追記し、新しいテストファイルは作らない。

1. 長い絶対パスの実フォント測定幅＋余白以上へ、絶対パス列が拡張される
2. 絶対パス列の`stretch`が無効で、画面幅に合わせて縮まない
3. 長い絶対パスを持つ候補を選択すると、`Candidate.absolute_path`と完全一致する文字列を表示する
4. 検索語変更や異常時の候補クリアで、古いパスを残さず初期案内と最小列幅へ戻す
5. パス表示の更新前後で、Audit、クリップボード、確定パス、検索語、入力状態、候補一覧が変化しない

マウス・キーボードごとに同じ状態更新テストを重複させない。`<<TreeviewSelect>>`のバインド確認とハンドラの結果を1経路で固定し、ダブルクリックは既存のExplorer Preview結合テストへ表示確認を追加する。

## 8. Windows手動確認4項目

1. 現在は列内で切れる長い候補について、横スクロールを右端へ動かすと絶対パス末尾まで読める
2. 上下キーで候補を移動すると、選択中のパスが追従する
3. 候補のダブルクリックとEnterによるExplorer Preview、確定・コピーが従来どおり動作する
4. 最小ウィンドウサイズでも、全文表示が候補表や操作ボタンを使用不能にしない

業務パスは画面上で確認するだけとし、テスト出力や計画書へ記録しない。

## 9. 受け入れ条件4件

1. 長い候補の絶対パス列を最長パス幅まで拡張し、横スクロールで末尾まで読める。候補を選択した場合は一覧下にも全文を表示できる
2. 候補未選択または候補再描画後に、古い候補のパスを表示しない
3. マウス選択、キーボード選択、Explorer Previewと表示内容が同じ候補を指す
4. 全文表示だけでは、確定、Audit、クリップボード、検索語、入力状態、候補順を変更しない

MVP 0、Explorer Preview、ローカルファイルD&Dの受け入れ条件とは別建てで記録する。

## 11. 主なリスクと対策

| リスク | 対策 |
|---|---|
| 再検索後も古いパスが残る | 候補再描画の先頭で初期案内へ戻す |
| 表示とPreview・確定の候補がずれる | 3経路で既存`_selected_candidate_path()`を共用する |
| 長いパスで画面が縦に広がる | 候補領域内で折り返し、最小サイズを実機確認する |
| 長いパス列が画面幅へ縮められる | `stretch=False`とし、横スクロールで確認する |
| 候補更新後も以前の列幅が残る | `_clear_candidates()`で480pxへ戻してから再計算する |
| 選択だけで既存状態が変わる | 表示用`StringVar`以外を書き換えず、前後比較テストで固定する |
| 実業務パスがログへ残る | 表示はメモリ上だけとし、新規ログやAudit項目を作らない |

## 13. 実装・検証結果

2026-08-03に、計画どおり新規モジュールや依存関係を増やさず実装した。

- 候補件数表示とExplorer Preview案内の間に、選択中候補の絶対パス全文を折り返して表示する欄を追加した
- 実利用指摘を受け、最長候補パスを実フォントで測定し、絶対パス列を測定幅＋24pxまで拡張する処理を追加した
- 絶対パス列の`stretch`を無効にし、横スクロールでパス末尾まで到達できる構造へ変更した
- 候補クリア時は列幅を480pxへ戻し、新しい候補に合わせて再計算するようにした
- `<<TreeviewSelect>>`、ダブルクリック、既存の`_selected_candidate_path()`を共用し、表示・Preview・確定が同じ候補を参照するようにした
- 候補再描画時と候補未選択時は初期案内へ戻し、古い候補パスを残さないようにした
- 長い合成候補パスを使い、完全一致表示、折り返し設定、再描画時のクリア、表示だけでは副作用がないことをWindows GUI結合テストで確認した
- ヘッドレステスト91件合格、6件選択除外
- Windows結合テスト5件合格、実MSGパス未設定の1件だけ選択除外
- Ruff lint合格、format check 22ファイル合格

実業務カタログを使った目視確認では、業務パスをテスト出力や本書へ記録しない。利用開始時に、§8の4項目を画面上で最終確認する。
