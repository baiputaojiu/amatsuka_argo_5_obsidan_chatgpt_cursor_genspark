## 1. 文書の目的

本書は、OneDrive年度別業務フォルダ向け「保存先レコメンダー」のMVP要件を定義する。

本プロダクトはファイルを自動整理するツールではない。ローカルファイルとICSの文脈を読み取り、既存保存先または新規フォルダ案を提示し、人が最終判断するためのデスクトップ向け支援ツールである。

正解率100%ではなく、次の状態を目指す。

- 保存先を探す時間を短縮する
- 第一候補が外れても、代替候補から短時間で選べる
- 推薦理由を人が確認できる
- 判断材料が足りない場合に無理に断定しない
- 不可逆操作と無断の外部送信を行わない

---

## 2. 背景・解決する問題

対象OneDriveでは、年度フォルダとテーマ別サブフォルダを使って業務資料を整理している。一方、次の問題がある。

- ルート直下や未整理場所に、保存先未決定のファイルが滞留する
- 保存先を思い出す、検索する、比較する作業に時間がかかる
- 既存フォルダへ寄せるか、新規テーマフォルダを作るかの判断が都度必要になる
- フォルダ構成は取得済みだが、振り分け判断は人手のままである
- 既存構成には、重複、曖昧さ、命名揺れ、分類軸の混在がある

対象年度の実例では、分類A / 分類B / 分類C / Sub / Not in charge / 雑用などの役割軸に加え、テーマ、日付、人名、メーカー名、資料種別、一時状態などが混在している。

---

## 3. プロダクトの一文定義

ICSとその関連ファイル、またはファイル単体を自動判別し、更新可能な年度別OneDriveフォルダ構成から保存先を提案するとともに、提案に納得できない場合のCodex相談用プロンプトを提示する、個人用デスクトップアシスタント。

---

## 4. 用語

| 用語 | 意味 |
|---|---|
| モードA | 外部AI、Auditログ、過去の採用履歴を使わず、ローカルのルールと類似度計算で行う通常判定 |
| Codex相談 | モードAに納得できないとき、ユーザーがPCにインストールされたCodexへファイルとプロンプトを手動で渡して相談すること |
| 保存先カタログ | OneDrive年度別業務フォルダのディレクトリ構成と役割メモを、ローカルで検索可能にした索引 |
| RoutingCase | 1つのICSと、そのICSに関連付けられた0件以上のファイルから成る解析単位 |
| 保存先未定 | 判断材料が不足するファイルを一時的に置く、人が作成した既存フォルダ |
| Auditログ | モードAの提案と人の最終判断を、後日のプログラム改善相談の材料として残すローカル記録 |

### 重要な用語上の決定

- アプリ内に「モードBの判定結果」は存在しない。
- アプリが表示する判定結果はモードAのみである。
- Codex相談は、アプリ外でユーザーが手動実施するエスカレーション手段である。
- アプリはCodex回答の取得、貼り付け、解析、比較表示を行わない。

## 5. 対象ユーザー・環境・範囲

### 5.1 対象ユーザー

- OneDrive業務フォルダを利用する本人1名
- 日本語を使用するWindows業務PCユーザー
- MVPは個人専用とし、複数ユーザーの権限管理は行わない

### 5.2 対象OneDriveルート

```text
C:\Users\example\OneDrive - Example Organization
```

実装上は設定から変更可能とする。

### 5.3 推薦対象

- `ARCHIVE_FY_01`、`010_FY_PREVIOUS`などの年度別業務フォルダ
- 年度フォルダ配下の既存サブフォルダ
- 年度フォルダ配下に作成する新規フォルダ案
- 現行年度配下の「保存先未定」フォルダ

### 5.4 MVP対象外

- 年度フォルダ外のTeams / Copilot / OneNote等の自動保存先
- キャリア
- プライベート
- データ避難
- 年度外の会議・録画・画像等の共通フォルダ
- OneDrive全体の大規模再編

## 6. 主要な利用シナリオ

- 添付情報を含むICSを投入する
- 添付を含まないICSを投入する
- ICSとPDF・Office・画像・図面を一緒に投入する
- PDFまたはOfficeファイルを単体で投入する
- 画像・図面をICSと一緒に投入し、ICSの文脈から保存先を判断する
- 画像・図面を単体で投入し、ファイル名から判断する
- モードAの第一候補を採用する
- 代替候補を採用する
- 別の既存フォルダへ手動修正する
- 新規フォルダ案を採用する
- 判断不能なファイルを「保存先未定」に置く
- モードAに納得できない場合、表示された添付一覧とプロンプトを使ってCodexへ相談する
- OneDriveフォルダ構成が変わったとき、保存先カタログを更新する
- 誤判定が蓄積したとき、Auditログを材料としてCodexへプログラム改善を相談する

## 7. MVPスコープ

### 7.1 Must

- 個人専用のGUIを提供する
- 入力種別を事前選択させず、投入ファイルから自動判定する
- ICS、PDF、Word、Excel、PowerPoint、画像、図面、その他ファイルを識別する
- ICSと関連ファイルを自動グルーピングする
- 自動グルーピング結果を人が修正できる
- ICSから件名、説明、日時、主催者、参加者、場所、添付情報を抽出する
- PDF・Office本文をローカル抽出する
- 画像・図面はファイル名、ICS、同じ案件の関連文書から判断する
- 年度別業務フォルダを読み取り専用で走査し、保存先カタログを作る
- GUIから保存先カタログを更新できる
- 既存保存先と新規フォルダ案を同じ候補群で評価する
- 第一候補、信頼度、理由、代替候補を表示する
- 低信頼時に「保存先未定」を提示する
- 新規案に、既存の親パス、提案名、理由、手動作成手順を含める
- モードA結果と同じ画面に、Codexへ添付するファイル一覧と相談用プロンプトを表示する
- 人の採用、却下、修正、保存先未定の選択を必須にする
- 人の最終判断を最小限のAuditログへ記録する
- Auditログを使った改善相談手順を「判定改善」タブへ表示する
- Auditログを日常の判定へ自動反映しない
- ファイル移動、保存、フォルダ作成、AI送信を実行しない

### 7.2 Should

- カタログ更新時に追加、消失、名称変更候補、移動候補を差分表示する
- フォルダごとの役割メモを編集・保持できる
- 似たフォルダ名、重複、命名揺れを警告する
- 複数ファイルへ同じ保存先を一括適用できる
- 指示書とCodex相談プロンプトをクリップボードへコピーできる
- カタログが古い場合に更新を促す
- 過去案件を再判定し、改善前後の結果を人が比較できる

### 7.3 Won't

- ファイルの自動移動・自動保存
- フォルダの自動作成
- Codexや外部AIへの自動送信
- AI APIの利用
- Codex回答の自動取得・取り込み・比較
- Auditログによる自動学習
- 過去の採用先を使った自動加点
- 判定ルールや閾値の自動変更
- Outlook COMによるメール自動取得
- OCR
- CAD図面の内容解析
- 暗号化解除
- 破損ファイル修復
- 複数利用者対応
- GCP・Google Calendar連携

## 8. 入力仕様

### 8.1 統一入力

- 入力種別の選択画面は設けない
- ファイルをD&Dまたは複数選択する
- アプリが形式を自動判定する
- 自動判定した形式と関連付けを一覧表示する
- ユーザーが誤判定・誤関連付けを修正できる
- 任意の補足メモを入力できる

### 8.2 対象形式

| 種別 | 例 | MVPでの扱い |
|---|---|---|
| ICS | `.ics` | ICS文脈を抽出する |
| PDF | `.pdf` | テキスト抽出する |
| Word | `.docx`, `.doc` | テキスト・見出しを抽出する |
| Excel | `.xlsx`, `.xls` | シート名・セル文字列を抽出する |
| PowerPoint | `.pptx`, `.ppt` | スライドタイトル・本文を抽出する |
| 画像 | `.png`, `.jpg`, `.tif`等 | 内容解析せず、名前とICS文脈を使う |
| 図面 | `.dwg`, `.dxf`等 | 内容解析せず、名前とICS文脈を使う |
| その他 | 上記以外 | ファイル名中心の不透明ファイルとして扱う |

### 8.3 形式判定

1. ファイルの存在と読み取り可否を確認する
2. ファイルサイズを確認する
3. 内部シグネチャを確認する
4. 拡張子と照合する
5. 対応パーサーを決定する
6. 拡張子と内部形式が異なる場合は警告する

### 8.4 ファイル名の比較用正規化

元のファイル名は変更せず、判定用の正規化名を生成する。

- Unicode NFKC正規化
- 全角英数字の半角化
- 英字の小文字化
- URLエンコード解除
- 連続空白の正規化
- 拡張子の分離
- 比較時のみ`- コピー`、`_copy`、`(1)`、`修復済み`等を弱める
- 日付、案件番号、設備名、固有名詞候補を分離する

## 9. ICS・関連ファイルの自動グルーピング

### 9.1 基本規則

- 1つのRoutingCaseは、0件または1件の主ICSと、0件以上の関連ファイルから成る
- 同じ案件内でも推薦と最終判断はファイル単位で行う
- 1ファイルは原則として1つのRoutingCaseだけに所属する

### 9.2 ICSが1件

- 同時投入された非ICSファイルを、そのICSの関連候補とする
- `ATTACH`と一致するファイルは明示的な添付として扱う
- `ATTACH`がなくても、同時投入による関連として仮グループ化する
- ユーザーが関連を解除できる

### 9.3 ICSが複数

次の優先順位で関連付ける。

1. `ATTACH`のファイル名と完全一致
2. 正規化後のファイル名と一致
3. ICS本文に対象ファイル名が明記されている
4. 案件番号・設備名・固有語が一致
5. 日付と主題が一致
6. 同時投入だけが根拠

1～3は自動関連付けできる。4～6だけの場合はユーザー確認を必須にする。

### 9.4 ICSがない

- 各ファイルを独立したRoutingCaseとする
- 自動的に複数ファイルを1案件へまとめない
- ユーザーが明示的にまとめることは可能とする

### 9.5 ICSだけ

- ICS自体を1件の保存対象として扱う
- `SUMMARY`、`DESCRIPTION`等を本文相当として利用する

### 9.6 ICSから抽出する項目

- `SUMMARY`
- `DESCRIPTION`
- `DTSTART`
- `DTEND`
- `ORGANIZER`
- `ATTENDEE`
- `LOCATION`
- `UID`
- `ATTACH`

### 9.7 関連付け信頼度

| 信頼度 | 条件 |
|---|---|
| 確定 | ユーザー指定、ATTACH完全一致、埋め込み添付 |
| 高 | 正規化名一致、ICS本文にファイル名記載、一意な案件番号一致 |
| 中 | 複数の案件語・日付が一致、ICSが1件で同時投入 |
| 低 | 同時投入以外の根拠がない、複数ICSから区別できない |

関連付け信頼度が低いICS文脈は、保存先スコアへ強く反映しない。

### 9.8 実装前確認事項

一般的なICSは通常メール本体ではなく予定・会議情報を表す。業務で利用する実物ICSを最低1件確認し、`ATTACH`が埋め込み、ローカル参照、URL、名称のみのどの形式かを確認する必要がある。

## 10. 本文・特徴抽出

### 10.1 ICS

- 件名、説明、日時、主催者、参加者、場所、添付情報を抽出する
- 定型署名、定型免責文、会議システムの定型文、長い過去引用は弱める

### 10.2 PDF・Office

- タイトル
- 見出し
- 本文
- 文書プロパティ
- シート名
- スライドタイトル
- 頻出する固有語

### 10.3 画像・図面

MVPでは内容を解析しない。次だけを利用する。

- ファイル名
- 拡張子
- ICS文脈
- 同じRoutingCaseにあるPDF・Office文書の主題
- ユーザー補足メモ

推薦理由に、対象画像・図面自体の内容を解析していないことを明記する。

## 11. 保存先カタログ

### 11.1 目的

- OneDrive年度別業務フォルダのディレクトリ構成をローカル検索可能にする
- 毎回OneDrive全体を走査せず、候補検索を高速化する
- フォルダ名だけでなく、親パスと役割メモを判定に使う

### 11.2 収録対象

- `NNN_YYYY年度`（3桁管理番号＋4桁年度）形式の年度フォルダ
- 年度フォルダ配下の全サブフォルダ
- フォルダパス、年度、大分類、親子関係、役割メモ、別名

### 11.3 収録しないもの

- 配下ファイル一覧
- ファイル本文
- 実際の業務ファイル名一覧
- 年度外フォルダ

### 11.4 更新

- GUIの「フォルダ構成を更新」から手動実行する
- 起動時に自動走査しない
- 最終更新から7日以上で更新を促す
- 更新前に新旧差分をPreviewする
- ユーザー確定後に新カタログへ切り替える
- 直前の正常カタログを1世代保持する

### 11.5 差分種別

- 追加
- 消失
- 名称変更候補
- 移動候補
- 大分類変更
- 役割メモ孤立

### 11.6 異常な更新の防止

次の場合は更新を中止して旧カタログを維持する。

- OneDriveルートが見つからない
- 現行年度フォルダ全体が見つからない
- 全フォルダの20%以上が一度に消失した
- 複数年度が同時に消失した
- アクセス拒否が大量発生した
- 走査が中断された
- OneDrive同期中・オフラインが疑われる

### 11.7 役割メモ

保持項目：

- 用途
- 入れる資料の例
- 入れない資料の例
- 略称・旧称
- 代表的な資料形式
- 任意メモ

方針：

- OneDriveやObsidianへ自動書き込みしない
- アプリのローカルランタイム領域に保存する
- Auditログから自動生成・自動変更しない
- フォルダ名称変更を人が確認した場合に限り引き継ぐ

## 12. 年度判定

- 年度は4月1日から翌年3月31日までとする
- 4月1日に現行年度を切り替える
- 4月1日から7月31日までは、現行年度と前年度を通常候補に含める
- 8月1日以降は現行年度を標準探索範囲とする
- ユーザーが年度を手動上書きできる
- 文書内の日付だけで年度を決めない
- 現行年度フォルダが存在しない場合は、自動作成せず警告と手動作成手順を出す

主な分類：

- Input
- Main
- Output
- Sub
- Not in charge
- 雑用
- 保存先未定

### 13.1 Input

- 他部署・外部から受領した参考資料
- 市場・顧客情報
- 規定
- マニュアル
- 組織図
- 年間スケジュール
- テンプレート
- 勉強会資料

### 13.2 Main

- 本人が主管する継続テーマ
- 設備開発
- 仕様検討
- 評価・試験
- 提案
- 図面
- 工事
- 予算管理
- 課題管理

### 13.3 Output

- 週報
- 月報
- 検討会資料
- 報告書
- 提出資料
- 結果まとめ

### 13.4 Sub

- 本業を支援する継続的な副テーマ
- 知財
- 部門横断の補助活動

### 13.5 Not in charge

- 外部から届いたという理由だけでは推定しない

### 13.6 雑用

- 一時的な社内事務

## 14. モードAの判定方法

### 14.1 使用するもの

- 明示ルール
- 正規化したファイル名
- ICS文脈
- PDF・Office本文
- フォルダ名・親パス
- 役割メモ
- 完全一致・部分一致
- 文字n-gram等のローカル文字列類似度

### 14.2 使用しないもの

- Codex
- 外部AI
- AI API
- Auditログ
- 過去の採用履歴
- 自動学習

### 14.3 採点

既存候補と新規候補を同じ100点尺度で評価する。

| 評価項目 | 点数 |
|---|---:|
| 主題・テーマとの一致 | 0～35 |
| ICS文脈との一致 | 0～20 |
| 対象ファイル本文との一致 | 0～20 |
| 年度・大分類との一致 | 0～15 |
| 命名・階層・役割メモとの整合 | 0～10 |

主な減点：

- 内容と用途が明確に矛盾：最大25点
- 類似する既存フォルダとの重複：最大20点
- 上位候補が区別できない：最大15点
- ICS関連付けが曖昧：最大15点
- 根拠がファイル名だけ：最大15点
- 一時案件なのに恒久テーマを作ろうとしている：最大15点

### 14.4 既存候補を十分適切とする基準

- 70点以上
- 年度・大分類の重大な矛盾がない
- 少なくとも2種類の根拠がある
- フォルダ用途を説明できる

ただし、新規案の得点が上なら新規案を第一候補にできる。既存候補を無条件に優先しない。

### 14.5 接戦

- 1位と2位の差が5点未満なら接戦と表示する
- 接戦時は高信頼にしない
- 完全同点の場合のみ、操作の少ない既存フォルダを上に表示する
- 同点処理を理由に明記する

## 15. 信頼度

信頼度は正解確率ではなく、推薦根拠の強さを表す。

### 高

- 第一候補80点以上
- 第二候補との差15点以上
- 2種類以上の独立した根拠
- 重大な警告なし

### 中

- 第一候補65点以上
- 第二候補との差5点以上
- 一部情報が不足していても理由を説明できる

### 低

- 第一候補65点未満
- 上位候補が接戦
- ファイル名中心
- ICS関連付けが低信頼
- 本文抽出失敗
- 新規作成の継続性が不明

---

## 16. 候補種別と新規フォルダ命名

### 16.1 既存フォルダ

- 実在し、カタログ上で有効なパスだけを提示する
- 消失・未確認・対象外フォルダは候補から除外する

### 16.2 継続テーマの新規案

```text
（大分類）テーマ名
```

条件：

- 3か月以上継続する見込み
- 今後も複数の資料が追加される
- 独立した業務責任、設備、プロジェクトとして説明できる
- 年度フォルダ直下に作成する

### 16.3 一時案件の新規案

```text
YYYYMMDD_案件名
```

条件：

- 会議、試験、出張、問い合わせ等
- 日付または期間が明確
- 既存テーマフォルダ配下に作成する
- 1件のICSと添付で完結する可能性が高い

### 16.4 新規案の制約

- 親は既存フォルダに限定する
- MVPでは新規フォルダを二階層同時に提案しない
- 人名だけの名称は原則避ける
- 類似する既存フォルダがあれば警告する
- 自動作成しない

### 16.5 保存先未定

推奨パス：

```text
＜現行年度フォルダ＞\（Pending）未分類
```

- ユーザーが事前に手動作成する
- 設定画面で実在パスを登録する
- 最高点55点未満、重大な矛盾、判断材料不足等で第一候補にする
- 55～64点では低信頼候補と並べ、保存先未定を目立つ選択肢にする
- 保存先未定は失敗ではなく正常な保留結果とする

## 17. 出力仕様

ファイルごとに次を表示する。

- ファイル名
- 第一候補
- 既存 / 新規 / 保存先未定
- 対象年度
- 大分類
- 信頼度
- 推薦理由
- 利用した判定材料
- 利用できなかった判定材料

理由は「類似度が高い」だけで終わらせず、ICS、本文、ファイル名、フォルダ名、役割メモのどれを根拠にしたかを説明する。本文の長い転載は行わない。

## 18. Codex相談支援

### 18.1 基本動作

モードA結果と同じ画面に、常に次の案内を表示する。

> モードAの回答に納得できない場合は、以下のファイルをPCにインストールしたCodexへ添付し、表示されたプロンプトを送信してください。

表示するもの：

- 添付するICS
- 添付する対象ファイル
- 判定根拠に使った関連ファイル
- 添付しなくてよいファイル
- コピー可能な相談用プロンプト

### 18.2 添付対象

原則として次を含める。

- 判定対象ファイル
- 文脈として利用した主ICS
- 画像・図面の判断根拠に使ったPDF・Office文書

単に同じ案件に含まれるだけで判定に使っていないファイルは除外する。

### 18.3 プロンプトに含める情報

- 対象ファイル
- 関連ICS
- 対象年度
- モードAの第一候補・信頼度・理由・代替候補
- 関連する既存フォルダ10～30パス程度
- 新規フォルダの命名規則
- 判断不能なら保存先未定とする指示
- ファイル移動・フォルダ作成を行わない制約

### 18.4 明示的な非機能

- アプリはCodexへ送信しない
- Codex回答を取得しない
- Codex回答を貼り付ける欄を設けない
- Codex回答をAuditログへ保存しない
- Codex相談後の最終選択はユーザーがアプリ上で手動入力する

## 21. Auditログ

### 21.1 目的

- モードAが何を提案し、人がどこを選んだか確認する
- 繰り返される誤判定を後日発見する
- ユーザーが明示的に希望したとき、Codexへプログラム改善を相談する材料にする

### 21.2 日常判定からの分離

- Routing EngineはAuditログを読み込まない
- 過去の採用先を自動加点しない
- Auditログからルール、閾値、役割メモを自動変更しない
- 自動学習・再学習をしない
- Auditログの有無・内容によってモードA結果を変えない

### 21.3 記録項目

- 判定日時
- ケースID
- ファイル名
- ファイル形式
- ICS文脈の有無
- 本文抽出状態
- カタログバージョン
- 判定プログラムバージョン
- モードAの第一候補
- 代替候補
- 信頼度
- スコア
- 理由区分
- 人の判断
- 最終保存先
- エラーコード

### 21.4 記録しないもの

- ファイル本文
- ICS本文
- Codex相談用プロンプト
- Codex回答
- 閲覧者
- 保存期間フィールド
- 自動学習用特徴量

ログはユーザーが明示的に削除するまでローカル保持する。

---

## 22. 判定改善タブ

### 22.1 対象抽出

- モードAと最終保存先が異なる
- 代替候補が選ばれた
- 手動修正された
- 保存先未定になった
- 推薦が却下された
- エラーになった

### 22.2 手順

1. 改善対象のAudit記録を選ぶ
2. 必要な元ICS・関連ファイルを再選択する
3. Codexへ渡す情報をPreviewする
4. 改善相談用プロンプトを生成する
5. Codexへ手動で相談する
6. 原因、改善案、影響範囲、テスト案を確認する
7. 実装したい改善だけを選ぶ
8. 改めてCodexへ実装を明示的に依頼する
9. 改善後に過去案件を再判定する

### 22.3 制約

- 判定改善タブ自身はコードを変更しない
- 設定、閾値、役割メモを自動変更しない
- 改善相談時も自動送信しない
- 一度の相談対象は最大20件程度とする

## 24. 保存領域と分離

想定ランタイム領域：

```text
%LOCALAPPDATA%\OneDriveDestinationRecommender\
├─ settings.json
├─ catalog\
│  ├─ current.json
│  ├─ previous.json
│  └─ role_memos.json
├─ audit\
│  └─ audit.jsonl
├─ logs\
│  └─ app-YYYYMMDD.log
└─ temp\
```

### 保存方針

- 設定、カタログ、Audit、通常ログを分離する
- Git、OneDrive業務フォルダ、Obsidian Vaultへランタイムデータを保存しない
- 抽出本文はセッション終了後に保持しない
- 一時データは正常終了・キャンセル時に削除する
- 通常ログには原則としてファイル名、絶対パス、本文を出さない
- 設定・カタログ更新は一時ファイルへ書いた後に安全に置き換える

## 25. エラー処理

| エラーコード | 内容 |
|---|---|
| `ENCRYPTED_FILE` | 暗号化されている |
| `TEXT_NOT_EXTRACTABLE` | スキャンPDF等でテキストを抽出できない |
| `CORRUPT_FILE` | 破損している |
| `FILE_TOO_LARGE` | 初期上限50MBを超える |
| `UNSUPPORTED_FORMAT` | 未対応形式 |
| `ACCESS_DENIED` | 読み取り権限がない |
| `FILE_NOT_FOUND` | ファイルが存在しない |
| `INVALID_ICS` | ICS解析に失敗 |
| `AMBIGUOUS_ATTACHMENT` | ICSと関連ファイルを特定できない |
| `CATALOG_UPDATE_FAILED` | カタログ更新失敗 |
| `CURRENT_YEAR_FOLDER_NOT_FOUND` | 現行年度フォルダが存在しない |

本文抽出失敗時：

- エラーを表示する
- ユーザーが「ファイル名とICSだけで続行」を選べる
- 続行時は必ず低信頼とする
- 判断材料が不足する場合は保存先未定とする
- 1ファイルの失敗で、他ファイルの解析を停止しない

## 26. 非機能要件

### 26.1 安全性

- OneDriveアクセスは読み取り専用
- ファイル移動・フォルダ作成・削除機能を判定処理へ持たせない
- 外部ネットワークなしでもモードAを利用可能

### 26.2 プライバシー

- 本文はメモリまたは一時領域だけで扱う
- 本文を通常ログ・Auditログ・カタログへ保存しない
- Codexへ渡すファイルを具体名で表示する
- 自動送信しない

### 26.3 再現性

- 判定プログラムとカタログのバージョンを結果へ記録する
- スコア内訳を確認可能にする
- Auditログを削除しても同条件のモードA結果は変化しない

### 26.4 可用性

- 個別ファイルの失敗で全体停止しない
- カタログ更新失敗時は前回正常版を使う
- 解析不能でも保存先未定を選べる
- 解析をキャンセルできる

### 26.5 応答性目標

- 通常画面操作は1秒以内に反応
- カタログ内候補検索は2秒以内
- 解析中は定期的に進捗更新
- 長時間処理でGUIを固めない

### 26.6 保守性

- GUI、Application Services、Domain、Connectors / Parsersを分離する
- ファイル形式ごとにパーサーを分離する
- 採点ルールとGUIを分離する
- Routing EngineはAudit Readerへ依存しない
- エラーコードを一元管理する

## 27. MVP受け入れ条件

固定の正解データ、評価件数、現状平均時間、正解率の数値目標はMVP必須条件としない。次のシナリオ成立を受け入れ条件とする。

### 入力・関連付け

- ICS、PDF、Office、画像、図面を自動判定できる
- ICSと同時投入されたファイルを関連付けできる
- 複数ICSで曖昧なファイルを人に確認させる
- ICSがなければ各ファイルを独立案件にする
- 自動関連付けを人が修正できる

### 抽出・判定

- PDF・Office本文をローカル抽出できる
- 画像・図面をICSまたはファイル名から判定できる
- 既存、新規、保存先未定を候補にできる
- 第一候補、理由、信頼度、代替候補を表示できる
- 接戦時に高信頼としない
- 判断不能時に保存先未定を第一候補にできる

### 年度

- 4月1日に現行年度を切り替える
- 4月1日～7月31日に前年度も候補へ含める
- 8月1日以降は前年度を標準探索から外す
- 年度を手動上書きできる

### カタログ

- フォルダ追加、消失、名称変更候補、移動候補を差分表示できる
- 大量消失等の異常時に更新を中止できる
- 更新失敗時に旧カタログを維持できる
- 役割メモを人の確認後に名称変更先へ引き継げる

### Codex相談

- モードA結果と同時に相談案内を表示する
- 添付すべき具体的なファイル名を表示する
- 相談用プロンプトをコピーできる
- Codexへ自動送信しない
- Codex回答をアプリへ取り込まない

### Audit・改善

- モードA結果と人の最終判断を記録できる
- 本文を記録しない
- Auditログが日常判定へ影響しない
- 改善相談用プロンプトを生成できる
- コードやルールを自動変更しない

### 安全性

- 自動移動、自動保存、自動フォルダ作成、自動送信が発生しない
- 暗号化、スキャン、破損、巨大ファイルで原因の分かるエラーを表示する
- キャンセルしても元ファイルに変化がない
