## 1. 文書情報

- 対象：OneDrive業務フォルダ向け「保存先レコメンダー」

## 2. 目的と対象範囲

WindowsデスクトップまたはExplorerに存在するファイルを、保存先レコメンダーの入力欄へドラッグ＆ドロップ（以下、D&D）して投入できるようにする。

今回扱うもの：

- デスクトップまたはExplorer上のローカルファイル
- Explorerで複数選択したファイル
- ローカルに保存済みのMSG 1件
- PDF、Office、画像、図面等の通常ファイル1件または複数
- 日本語、空白、全角・半角括弧を含むパス

今回扱わないもの：

- Outlook画面に表示されたメールの直接D&D・直接取得
- フォルダの投入・走査
- アプリからExplorerへのドラッグ
- ファイルのコピー、移動、削除、名前変更
- Windowsショートカット（`.lnk`）のリンク先解決
- 複数MSG、MSGと通常ファイルの混在
- D&D専用画面、設定、ログ、履歴、アニメーション

Outlook画面からの直接D&Dは、実ファイルのパスを渡すデスクトップ・ExplorerのD&Dとはデータ形式が異なるため、別改修とする。

---

## 3. 操作仕様

- 既存の入力ファイル一覧をドロップ先とし、新しい画面は設けない
- 入力欄の近くに「デスクトップまたはExplorerからファイルをここへドロップできます」と常設表示する
- ドロップされたファイル群を新しい1案件として扱い、現在の入力へ追記せず置き換える
- 新入力の処理に成功した場合だけ、入力、検索語、候補一覧を置き換える
- 失敗した場合は、直前の入力、検索語、候補一覧、確定パスを維持する
- 「ファイルを選択」ボタンを残し、D&Dが使えなくても従来操作を継続できるようにする

既存の入力規則を変更しない。

- MSGは1件だけ受け付ける
- MSG以外の複数ファイルは1案件として扱う
- 複数MSG、MSGと通常ファイルの混在は、既存の案内で全件拒否する
- フォルダが1件でも含まれる場合も全件拒否し、受け付け可能なファイルだけを抜き出さない
- ファイル名、MSG本文・件名・添付名からの検索語生成は変更しない

成功後の表示、確定パスのクリア、検索欄へのフォーカス、エラー案内は、現在のファイル選択と同じ処理を使う。

---

## 4. 安全性と不変条件

D&DはOSからローカルファイルのパスを受け取るだけとし、次を行わない。

- 元ファイルまたはOneDriveへの書き込み
- ファイルのコピー・移動・削除
- 外部サービスへの送信
- 保存先の確定またはクリップボードへのコピー
- D&D操作自体のAudit記録

実業務ファイル名と絶対パスは、既存の入力一覧表示とメモリ上の入力状態だけで扱う。D&D専用ログは作らない。

## 5. 技術方式

### 5.1 依存

`tkinterdnd2==0.6.2`をWindows限定の実行時依存として追加する案を第一候補とする。

- 既存の`tk.Tk()`は置き換えず、ルート作成後に`TkinterDnD.require(root)`を呼ぶ
- importとTk拡張の読込みはD&D初期化時まで遅延させる
- パッケージは`pyproject.toml`でバージョンを固定する
- 未導入または初期化失敗時はD&Dだけを無効化し、アプリとファイル選択を残す
- Windows以外ではD&Dを初期化せず、既存のヘッドレステストを維持する

現行版0.6.2には既存ルートへ適用する`TkinterDnD.require()`が用意されている。ただしバイナリを含む新規依存なので、採用は§7の実機検証に合格した場合だけ確定する。

通常の`pip install -e ".[dev]"`だけで個人利用環境へD&D機能を導入できるよう、optional dependencyには分けない。初期化失敗時のフォールバックは、インストール手順を増やすためではなく、アプリ全体の起動不能を防ぐために残す。

Win32の`WM_DROPFILES`をTkinterへ直接組み込む方式は、ウィンドウプロシージャの差し替え、64bit対応、終了時の解除等の独自管理が必要になるため採用しない。`tkinterdnd2`が不適合でも自動的にこの方式へ切り替えず、改めて判断する。

### 5.2 パス解析と既存処理の共用

ドロップイベントの生文字列を空白で`split()`せず、`root.tk.splitlist(event.data)`を使う。空白、日本語、括弧を含む単一・複数パスを変更しないためである。

`app.py`の現在の`_select_files()`から、選択済みパスを処理する部分を共通メソッドへ抽出する。

```text
ファイル選択 → パス取得 ─┐
                          ├→ _accept_files(paths) → session.select_files(paths)
D&D → splitlist ──────────┘
```

D&D側に入力判定を再実装せず、MSGとフォルダの規則は既存の`RecommenderSession.select_files()`へ集約する。`select_files()`はパス解決直後に各項目が既存ファイルであることを確認し、フォルダまたは存在しないパスを1件でも含む場合は`InputSelectionError`で全件拒否する。シェルコマンド文字列は組み立てない。

## 7. 実装前の依存検証（Step 0）

プログラム本体を変更する前に、現在のWindows・Python 3.12環境と一時領域のダミーファイルで次を確認する。

1. `tkinterdnd2==0.6.2`を導入し、既存の`tk.Tk()`へ`TkinterDnD.require(root)`を適用できる
2. デスクトップから単一ファイル、Explorerから複数ファイルの正しいパスを取得できる
3. 日本語、空白、括弧を含むパスを変更せず取得できる

5. 既存のファイル選択ボタンとExplorer Previewが動作する

失敗した場合は、プログラム本体と`pyproject.toml`を変更せず、結果を本計画書へ記録して再レビューを依頼する。

## 8. 検証計画と受け入れ条件

### 8.1 自動テスト4項目

既存のGUI結合テストへ3項目、既存のセッション単体テストへ1項目を追加し、新しいテストファイルは作らない。

1. GUI：`splitlist`で空白、日本語、括弧を含む単一・複数パスを、順序と内容を変えず共通処理へ渡す
2. GUI：D&Dとファイル選択が同じ入力状態、検索語、候補を生成し、D&DだけではAudit、クリップボード、確定パスを変更しない
3. GUI：D&D初期化に失敗しても画面が起動し、ファイル選択を利用できる
4. 単体：`select_files()`がフォルダを含む入力を全件拒否し、直前の入力状態を維持する

複数MSGとMSG・通常ファイル混在の拒否は既存の`test_session.py`で固定済みのため追加しない。

現在のセッション単体テストには、通常ファイルの実体を作らずパスだけを`select_files()`へ渡すものがある。`is_file()`追加後も各テストの目的を変えないよう、入力時点では`tmp_path`に空の一時ファイルを作る。「選択後に通常ファイルが消えてもCodex相談を続けられる」既存テストは、選択成功後に一時ファイルを削除する形へ直す。

ネイティブD&DイベントとOSの接続は、ヘッドレス環境で再現せず、Step 0とWindows手動確認で検証する。全既存テスト、Windows結合テスト、Ruff lint・format checkも実行する。

### 8.2 Windows手動確認

- デスクトップからPDF 1件を投入する
- Explorerから通常ファイル複数件を1案件として投入する
- 保存済みMSG 1件を投入する
- フォルダ、複数MSG、MSGと通常ファイルの混在を拒否する
- D&D後もExplorer Previewと確定・コピーを利用できる
- 通常権限で起動し、管理者権限での起動を前提にしない

### 8.3 受け入れ条件5件

1. WindowsデスクトップとExplorerの双方からローカルファイルを入力欄へドロップできる
2. 空白、日本語、括弧を含む単一・複数パスを変更せず受け取れる
3. MSG 1件、またはMSG以外の複数ファイルを、ファイル選択時と同じ規則・結果で処理でき、D&DだけではAudit、クリップボード、確定パスを変更しない
4. フォルダ、複数MSG、MSGと通常ファイルの混在を全件拒否し、直前の入力状態を維持できる
5. D&D初期化に失敗してもアプリを終了せず、従来のファイル選択で利用を継続できる

既存の候補判定、Explorer Preview、確定・コピー、Codex相談、Auditは既存テストで担保し、この小改修で二重管理しない。

## 10. 主なリスクと対策

| リスク | 対策 |
|---|---|
| 新規のTkバイナリ依存が動かない | Step 0を先に行い、失敗時は本体を変更しない |
| パッケージ未導入でアプリ全体が起動しない | 遅延読込みとフォールバックでボタン入力を残す |
| 空白入りパスを複数項目と誤認する | Tkの`splitlist()`を使う |
| フォルダ配下を意図せず一括投入する | フォルダを含む場合は全件拒否する |
| D&Dとファイル選択で挙動が分かれる | パス取得後の処理を共通メソッド1本にする |
| 失敗した入力で現在の候補が消える | 成功した場合だけ表示状態を置き換える |
| 権限差でD&Dできない | 通常権限で起動する前提をREADMEへ記載する |
| Outlook D&Dまで対応したと誤解される | 画面とREADMEに「デスクトップまたはExplorer」と明記する |
