# システム仕様書

## 1. 文書目的

本書は、経済アナリストの発言収集、予想抽出、市場実績評価、能力評価、現在予想統合を行う個人用アプリケーションの機能・構成・制約を定義する。

## 2. システム概要

### 2.1 名称

仮称：アナリスト予想検証アプリ。

### 2.2 利用形態

- Windows 11上のローカルターミナルアプリ。
- 個人・単一ユーザー。
- Obsidian Vaultを人間向けの保存・閲覧場所とする。
- AI処理はCursorまたはChatGPTで半自動実行する。
- 集計、採点、市場データ取得、グラフはPythonで行う。

### 2.3 目的

詳細は [PRODUCT_VISION.md](../05_計画/PRODUCT_VISION.md) を参照。

## 3. 用語

主要用語は [GLOSSARY.md](../04_参考資料/GLOSSARY.md) を参照。本文では「分析対象者」を評価する人物、「予測対象」を銘柄・指数・為替等として区別する。

## 4. システム境界

### 4.1 システムが行うこと

- 案件・フォルダ・ID・進捗の管理。
- AI用プロンプト生成。
- AI出力の形式検査・取込み。
- 原文、発言、予想、評価の関連付け。
- 無料市場データまたはCSVによる市場実績取得。
- 方向、時期、程度、早期実現、相対成績の計算。
- アナリスト能力と現在予想の集計。
- Markdown、CSV、PNG、将来はHTMLの出力。
- 次に行う作業の案内。

### 4.2 システムが行わないこと

- 自動売買、注文、資産管理。
- 外部公開、SNS投稿、他者への配信。
- 全媒体の完全網羅保証。
- 初期版での常時監視・完全自動AI実行。
- AIまたは市場データの正確性保証。

## 5. 利用シナリオ

### UC-01 新しい分析案件

1. ユーザーが分析対象者、期間、媒体等を入力。
2. Pythonが対象者ID、案件ID、フォルダ、状態、プロンプトを生成。
3. 次の推奨作業を表示。

### UC-02 情報源収集

1. AIが選択媒体を探索。
2. URL、日時、媒体、証拠情報、検索ログを出力。
3. Pythonが形式、URL重複、既存ハッシュを検査。

### UC-03 YouTube原文取込み

1. ユーザーが文字起こしを置く、または取得処理で保存。
2. AIが発言単位へ整理し、話者を推定。
3. 低確信度・重要発言は別AIが再検証。

### UC-04 予想抽出

1. AIが原文から予想表明を抽出。
2. 原文引用、位置、方向、時期、程度、条件等をJSON化。
3. PythonがSchemaと引用存在を検査。
4. 低確信度・高重要度だけAIレビュー。

### UC-05 予測対象解決

1. 原文に明示された対象を優先。
2. 不明ならAIが発言時点情報で候補提案。
3. 別AIが後知恵・適合性・ティッカー等を検証。
4. 不一致時のみAI裁定。
5. マッピングを固定し、市場評価後に書き換えない。

### UC-06 市場実績評価

1. Pythonが `yfinance`、FRED、CSVからデータ取得。
2. 開始価格、営業日、通貨、配当、分割を処理。
3. 方向、時期、程度、早期実現、相対成績を計算。
4. 評価状態と履歴を保存。

### UC-07 現在予想と過去実績

1. 指定期間の予想を一括管理。
2. 評価基準日時点の状態を計算。
3. 同一データから現在有効、評価完了、条件待ち等を表示。

### UC-08 次の行動案内

1. Pythonが依存関係、ファイル、DB状態を確認。
2. 推奨行動、理由、担当、入力、出力、代替案を表示。
3. 同内容を `NEXT_ACTIONS.md` 等へ出力。
4. Cursorが状態ファイルを読んで自然言語で案内できる。

## 6. 機能要件

### FR-01 案件管理

- 分析対象者、調査期間、基準日、媒体、重点対象を登録できる。
- 同一対象者の複数案件を区別できる。
- 期間重複を許容し、情報源重複を検出する。

### FR-02 媒体選択

- YouTube、ブログ、X、その他Webを個別選択できる。
- 未選択媒体は `not_requested` とする。

### FR-03 プロンプト生成

- 必要なプロンプトだけを生成する。
- Cursor版とChatGPT版を生成できる。
- 説明、実行タイミング、推奨能力、入力、出力、注意、コピペ用依頼文を含む。
- 案件には使用時点のスナップショットを保存する。

### FR-04 原文保全

- `raw`を上書きしない。
- ハッシュ、取得日時、出所、文字位置を保存する。
- `processed`から`raw`へ追跡できる。

### FR-05 YouTube話者推定

- 話者情報のない原文をセグメント化する。
- 動画メタデータ、会話文脈、発言時点以前の本人発言等から話者候補を推定する。
- 根拠、確信度、未解決状態を保存する。
- 判断不能を本人発言として強制登録しない。

### FR-06 予想認定

- 明示的予想、方向性予想、条件付き予想、投資推奨、シナリオ等を分類する。
- 現状分析、過去説明、選好、可能性の列挙を区別する。
- 本命のない両論併記を正式的中率から除外する。

### FR-07 再表明等

- 後日の再表明を新しい予想表明として数える。
- 転載、リンク共有、第三者引用を新しい表明にしない。
- 再表明、確信強化・低下、数値・時期修正、反転、撤回を関連付ける。
- 同じ予想系列を予想グループとして保持する。

### FR-08 複合予想

- 上昇、転換、下落等を構成予想へ分解する。
- 構成部分を個別評価し、親予想の部分的中も表示する。
- 構成数を独立予想件数として水増ししない。

### FR-09 時期

- 発言者明示、AI推定、システム既定を区別する。
- 期間不明は1、3、6、12か月観測する。
- 明示されていない期限を時期精度へ算入しない。
- 発言日時と公開日時を分ける。

### FR-10 予測対象

- 銘柄、指数、ETF、為替、コモディティ、業種、テーマ等を正規化する。
- 原文で言及した対象・構成銘柄を優先する。
- AI提案、AIレビュー、不一致裁定を記録する。
- 発言後情報の逆流を検査する。

### FR-11 市場実績

- 無料データを優先する。
- 株価、配当、分割、通貨、ベンチマークを区別する。
- 取得不能時はCSVを案内し、推測値を使わない。
- 取得元、取得日時、調整方式を保存する。

### FR-12 評価

- 単純方向判定と実際の変化率を保存する。
- 最大上昇、最大下落、時期ずれ、数値誤差を保存する。
- 投資推奨は絶対成績とベンチマーク相対成績を分ける。
- 早期実現を正式判定とは別に評価できる。
- AI推定値とシステム既定値を発言者の精度へ混入しない。

### FR-13 状態管理

- `not_started`、`active_on_track`、`active_off_track`、`active_indeterminate`、`fulfilled_early`、`failed_early`、`expired_hit`、`expired_miss`、`condition_pending`、`withdrawn`、`superseded`、`unevaluable` を扱う。
- 状態更新履歴を保存する。

### FR-14 調査網羅性

- 媒体調査状況、発見件数、取得率、処理率、検証率を表示する。
- 分母不明の一般検索に偽の割合を付けない。
- 検索語、使用機能、実行日時、確認範囲、取得不能理由を保存する。

### FR-15 アナリスト評価

- 方向、時期、程度、具体性、検証可能性、分析品質、修正能力を分離表示する。
- MVPは結果と機械計算可能な予想品質を優先する。
- 分野・期間・対象種別ごとに集計する。
- 件数不足を補正または注意表示する。

### FR-16 現在予想統合

- 同一人物の再表明を複数人分として数えない。
- 最新の有効な見解を代表とし、再表明回数を補助表示する。
- 過去成績、具体性、サンプル数、現在状態、経過時間を参照する。
- 賛成・反対双方と根拠を表示する。

### FR-17 レポート

- Markdown、CSV、PNGを生成する。
- 全予想、現在有効、評価完了、調査網羅性、未解決、対象者概要を生成する。
- 複数アナリスト段階で上昇候補、タイムライン、ヒートマップを追加する。

### FR-18 次行動案内

- 現在状態から一つの推奨行動と代替案を示す。
- 担当がAIかPythonかユーザーかを明示する。
- 使用プロンプト、入力、出力、完了後操作を示す。

### FR-19 バージョン・監査

- プロンプト、モデル、アプリ、DB、評価方法、マッピングのバージョンを保存する。
- 結果から原文、AI出力、市場データ、計算条件を追跡できる。

## 7. 非機能要件

### NFR-01 データ保全

- 原文変更禁止。
- DB取込みはトランザクション。
- 再実行で重複しない。
- DB更新・移行前にバックアップ。

### NFR-02 操作性

- 日本語で説明する。
- 色だけで状態を示さない。
- エラーに解決方法を含める。
- 通常利用でDB直接編集やプロンプト順暗記を求めない。

### NFR-03 再現性

- 同じ入力、プロンプト、モデル、評価方法を特定できる。
- 評価基準日時点のスナップショットを残す。

### NFR-04 性能

- ローカル進捗表示は数秒以内を目標とする。
- 市場データをキャッシュする。
- 中断・再開できる。
- 数十人、数万情報源、数万～十万予想を想定したSQLite索引を設計する。

### NFR-05 セキュリティ・個人利用

- APIキーを文書、ログ、Gitへ保存しない。
- 外部公開機能を持たない。
- AIサービスへ原文を入力する点を説明書へ記載する。
