# 実装上の暫定判断

## 1. 注意

この文書は `DECISION_LOG.md` ではなく、実装を止めないための暫定判断を記録する。正式決定を意味しない。ユーザー確認または技術検証によって変更でき、変更時は影響するデータ、migration、テスト、運用手順を確認する。

## 2. 暫定判断

### A-001 実装配置

- 暫定内容：正本資料がある `analyst_forecast_app_cursor_handoff/` をPythonプロジェクトのルートとする。
- 理由：仕様と実装を同じ配布単位に置き、外側のワークスペースにある無関係な既存プロジェクトを変更しないため。
- 影響：モノレポ内では他プロジェクトと並ぶ1段の配置になる（同名フォルダの二重ネストは解消済み）。
- 見直し条件：正本フォルダをGitルートへ移す方針が明示されたとき。

### A-002 Python対応範囲

- 関連：実装依頼、受入チェックリスト基盤
- 暫定内容：Python 3.12を基準にし、`requires-python` は3.12以上3.15未満とする。まず3.12で全検査を行う。
- 理由：仕様の原則を満たしつつ、着手環境に存在する3.14でも補助確認できるようにするため。
- 影響：3.11以前と3.15以降は現時点で保証しない。
- 見直し条件：依存ライブラリの対応状況または配布方式の決定時。

### A-003 設定とユーザー固有値

- 関連：OQ-002、OQ-004
- 暫定内容：Vaultルート、DB位置、AIモデル名、provider設定、確認閾値はYAML設定へ置く。CLI引数と `ANALYST_FORECAST_CONFIG` で設定ファイルを選べるようにする。
- 理由：実パスやモデル名をコード・Git管理ファイルへ埋め込まないため。
- 影響：初回に `init` が必要。テストは一時設定を使う。
- 見直し条件：正式なVault配置と配布方式が決まったとき。

### A-004 初回対象者

- 関連：OQ-001
- 暫定内容：実名を選ばず、テストでは「匿名アナリストA」という固定fixtureを使う。
- 理由：対象者選定を評価ロジックへ混入させず、個人固有値なしで再現するため。
- 影響：実媒体の網羅性や実発言に対するAI精度は確認しない。
- 見直し条件：最初の実対象者が指定されたとき。

### A-005 raw入力形式

- 関連：OQ-003、FR-04
- 暫定内容：MVPはUTF-8の1情報源1ファイルを受け取り、媒体、URL、発言日時、公開日時等はCLI引数で別に受け取る。タイムスタンプは本文に含めてもよいがPythonは意味解釈しない。
- 理由：本文を不変のまま保存し、将来の取得方法とapplication境界を分離するため。
- 影響：字幕形式固有の自動解析は未実装。
- 見直し条件：実際のYouTube文字起こしサンプルを確認したとき。

### A-006 ID発行

- 関連：T001、T002、DATA_MODELのID例
- 暫定内容：対象者IDは `A` と4桁連番、案件IDは `RUN-YYYYMMDD-NNN`、その他は仕様例の接頭辞と6桁連番をSQLite内の採番表からtransaction内で発行する。同じ正規化対象者名は既存IDを再利用する。
- 理由：人が読め、ローカル単一ユーザー環境で衝突を防げる最小方式だから。
- 影響：DBを分割した環境間では同じ人物に別IDが発行され得る。
- 見直し条件：複数DB統合または複数端末同期が要件になったとき。

### A-007 raw重複の範囲

- 関連：FR-04、T102、T205
- 暫定内容：SHA-256が同じrawはDB全体で同一SOURCEとして扱い、別案件では既存SOURCEを案件へ関連付ける。raw本体は複製・再処理しない。
- 理由：同一原文を差分だけ処理する確定方針を最も直接に満たすため。
- 影響：同じ本文でも出所が異なる転載を別SOURCEとして保存したい場合は、本文ハッシュだけでは表現不足となる。MVPでは既存SOURCEへの関係メタデータとして記録する。
- 見直し条件：転載・同文配信を独立した出所証拠として扱う実データが入ったとき。

### A-008 最小AI Schema

- 関連：T104～T108、P08
- 暫定内容：Schema 1.0.0は案件ID、SOURCE ID、プロンプト実行情報、予想表明、構成予想、原文引用、明示された評価対象と固定マッピング情報だけを必須範囲とする。Cursor版とChatGPT版で同じSchemaを使う。
- 理由：意味判断をAIへ残しながら、引用、参照、方向評価に必要な最小情報をPythonで検証するため。
- 影響：複雑条件、複数シナリオ、詳細分析品質は後続Schema版で拡張する。
- 見直し条件：匿名fixtureで不足が判明したとき、または第3段階着手時。

### A-009 低確信度の扱い

- 関連：AI受入条件、OQ-004
- 暫定内容：抽出確信度が設定値未満のAI出力はSchema適合でも `needs_review` とし、正式予想テーブルへ自動取込みしない。初期閾値は0.70で設定変更可能とする。
- 理由：低確信度を隠さず、検証前の正式登録を防ぐため。
- 影響：閾値変更で自動取込み対象が変わる。
- 見直し条件：実サンプルでレビュー量と誤り率を比較できたとき。

### A-010 最小対象マッピング

- 関連：D-010、FR-10、OQ-006
- 暫定内容：縦断fixtureでは原文が明示する既知symbolだけを使い、AI出力に `knowledge_cutoff`、根拠、検証状態、固定時刻を必須とする。テーマの候補提案はプロンプトとSchema境界までとし、市場結果を見た自動選択は実装しない。
- 理由：後知恵を避けたまま最小方向評価を通すため。
- 影響：テーマ・業種の実評価は未完了。
- 見直し条件：P11・P12の実出力を比較できたとき。

### A-011 最小方向評価の価格基準

- 関連：METHODOLOGY 9、14、15、T401、T402
- 暫定内容：providerが返す日足について、評価開始営業日の分割調整済み始値と、評価基準日以前の最終営業日の分割調整済み終値を比較する。providerは価格基準をメタデータへ明記し、未調整値や配当込み値との混同を禁止する。yfinance 1.5.1では実データ検証により `auto_adjust=False` のOHLCが株式分割をまたいでも連続することを確認し、追加の分割係数は適用しない。
- 理由：日足、開始時の始値、分割調整価格という正式方針を満たす最小の再現可能な基準だから。
- 影響：市場時間内公開と終了後公開の厳密な市場別時刻判定は未実装で、fixtureでは開始営業日を明示する。
- 見直し条件：実市場のタイムゾーン・取引時間処理を追加するとき。

### A-012 横ばい

- 関連：T401
- 暫定内容：開始値と終了値が等しい場合の実績方向は `flat` とする。上昇・下落予想はいずれも的中としない。
- 理由：等値を上昇または下落へ恣意的に含めないため。
- 影響：許容幅を使う横ばい判定は行わない。
- 見直し条件：資産別の最小変動幅を正式に定めるとき。

### A-013 市場provider

- 関連：OQ-007、FR-11
- 暫定内容：共通Protocolの背後にCSV、yfinance、FREDを置く。unit testは固定fixtureとCSVだけを使用し、yfinance・FREDは明示的integration testにする。FRED APIキー未設定はskipまたは取得不能として報告する。
- 理由：ネットワーク障害をテスト失敗と混同せず、取得不能値を推測しないため。
- 影響：通常のpytest成功だけでは実ネットワーク到達性を保証しない。
- 見直し条件：利用対象と運用上のintegration test頻度が決まったとき。

### A-014 最初に生成するプロンプト

- 関連：MVP第0・第1段階、P05、P08、P11、P12
- 暫定内容：話者推定、予想抽出、対象解決、対象解決レビューの4種類だけをCursor版・ChatGPT版で案件へsnapshotする。裁定は不一致が実際に発生した後に追加する。
- 理由：第0段階の技術検証と縦断経路に必要な範囲へ限定するため。
- 影響：媒体探索や最終レポート等のプロンプトはまだ生成されない。
- 見直し条件：縦断経路完了後。

### A-015 評価スコア

- 関連：OQ-005、D-012
- 暫定内容：方向の的中可否、実際の変化率、期間中最大・最小変化、状態を保存する。0～100点、統合点、能力断定は作らない。
- 理由：未決定式を正式仕様のように固定しないため。
- 影響：MVP第1段階に列挙された時期・程度・早期実現の完全評価は残課題となる。
- 見直し条件：技術検証データとユーザー承認を得たとき。
