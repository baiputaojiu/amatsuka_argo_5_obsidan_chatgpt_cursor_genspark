## 3. 明白な矛盾と実装ブロッカー

### 明白な矛盾

- 正式仕様同士に、今回の最小縦断経路を停止させる矛盾は見つからなかった。
- `MVP_PLAN.md` 第1段階は時期・程度・早期実現まで列挙する一方、現在の依頼は最初の経路を「最小の方向評価」と明示している。現在の依頼を優先し、方向評価を先に完成させ、残る評価軸は未実装として追跡する。仕様本文は変更しない。
- `DATA_MODEL.md` は全エンティティに固定ID、作成日時、更新日時、バージョンを要求するが、個別の項目一覧では一部が省略されている。全体原則を優先し、今回作る正式テーブルには監査列を共通で持たせる。

### blocking

- 現時点ではなし。
- Python 3.12未導入はローカルに隔離した環境を作成できるため、仕様上のブロッカーではない。
- 実Vault、対象者、AIモデル、FRED APIキーが未設定でも、匿名fixture、明示設定、ネットワーク分離テストで進行できる。

## 4. OPEN_QUESTIONSの分類

### blocking

- なし。

### configurable_default

- OQ-001 初回テスト対象者：匿名の固定fixtureを使う。実対象者は案件作成時の入力とする。
- OQ-002 Obsidian Vaultの実パス：CLI初期化引数またはローカル設定で与える。テストは一時ディレクトリを使う。
- OQ-003 YouTube文字起こし形式：MVPはUTF-8の1情報源1ファイルと、CLI引数で渡すメタデータを暫定入力形式とする。将来の自動取込みは同じapplication境界へ接続する。
- OQ-004 使用モデル割当：Cursor用、ChatGPT用を設定項目にし、未設定を明示する。意味判断を廉価モデルへ自動切替しない。
- OQ-007 無料市場データのカバー範囲：providerの優先順とintegration testの実行有無を設定可能にし、取得可否を実測結果として残す。取得不能値はCSV待ちまたは評価不能とする。

### later

- OQ-005 スコア計算式：方向の真偽と変化率だけを実装し、0～100点や統合重みは導入しない。
- OQ-006 ベンチマーク既定値：最小方向評価に不要。相対評価実装時に決める。
- OQ-008 X・一般Web検索の実証：第2段階以降。
- OQ-009 分析品質のMVP範囲：構造を保存できる余地だけ残し、意味採点は先行実装しない。
- OQ-010 実行ファイル配布方式：縦断MVPのPython実行を確認した後に決める。

## 5. 採用バージョン

2026-07-20時点で公開版を照会し、Python 3.12.10環境への導入、CLI起動、migration、Ruff、mypy、pytestで互換性を確認した。直接依存は `pyproject.toml`、導入済みの推移依存を含む全環境は `requirements.lock` に固定する。

- Python 3.12.10
- Typer 0.27.0、Rich 15.0.0
- SQLAlchemy 2.0.51、Alembic 1.18.5
- Pydantic 2.13.4、jsonschema 4.26.0、PyYAML 6.0.3
- pytest 9.1.1、Ruff 0.15.22、mypy 2.3.0
- yfinance 1.5.1、fredapi 0.5.2

公開最新版を固定した理由は、空の新規実装で旧版互換性を背負わず、Python 3.12向けに現在保守されている組合せを実測できたためである。yfinanceは実ネットワークで通常期間と株式分割をまたぐ期間を確認し、`auto_adjust=False` のOHLCを分割調整済み・配当調整なしの価格として使用する。FREDはAPIキー未設定のため、依存導入、provider境界、取得不能処理までを確認済みとし、実取得は未確認として状態文書へ残す。
