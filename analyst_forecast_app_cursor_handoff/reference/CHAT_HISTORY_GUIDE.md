# 会話全文をCursorへ渡す場合の取扱い

## 結論

会話全文を添付してよい。ただし、正式仕様ではなく「検討経緯を確認するための参考資料」として渡す。

## 推奨する保存場所

ユーザーがChatGPTから会話全文をエクスポートまたはコピーし、次の名前で保存する。

```text
reference/chat_history.md
```

Markdown化が難しければ `reference/chat_history.txt` でもよい。機密情報、APIキー、個人パス等が含まれていないか、保存前に確認する。

## なぜ正式仕様にしないのか

会話には次が混在するためである。

- 最初の思いつき。
- 検討途中の案。
- 後で撤回または修正した案。
- AIが提案したがユーザーが採用していない内容。
- 同じ用語の意味が途中で変わった箇所。

全文を最上位の指示として扱うと、古い案を実装したり、現在の仕様へ矛盾を持ち込んだりする危険がある。

## Cursorへ明示するルール

```text
reference/chat_history.md は背景資料です。正式仕様は docs/ と 00_Cursor引継ぎ/02_SPEC_AUTHORITY.md です。会話と正式仕様が矛盾する場合は正式仕様を優先してください。会話から新しい要件候補を見つけても直ちに実装せず、候補と根拠を報告してください。
```

このルールは初回依頼文と `.cursor/rules/analyst-forecast-app.mdc` にも記載済みである。

## 長すぎる場合

会話全文を常にコンテキストへ読み込ませる必要はない。まず正式仕様だけで実装し、次の場合だけ会話を検索させる。

- 設計理由を確認したい。
- 仕様書の表現が曖昧。
- 過去に却下された案か確認したい。
- ユーザーの懸念や優先順位を詳しく知りたい。

会話全文を毎回読ませると、コンテキストと処理時間を消費し、重要な実装箇所への注意が薄くなる可能性がある。

## 添付できない場合

会話全文がなくても実装できる。確定した判断は `DECISION_LOG.md`、目的は `PRODUCT_VISION.md`、未決事項は `OPEN_QUESTIONS.md` に整理されているためである。
