# 実装受入チェックリスト

## 1. 用途

Cursorが「実装できた」と報告した内容を、機能の存在だけでなく安全性・再現性・操作性まで確認する。MVP完了時には全必須項目へ、テストまたは実行証跡を付ける。

## 2. 基盤

- [ ] Windows 11でサポートするPythonバージョンとセットアップ手順が明記されている。
- [ ] 依存関係が固定され、クリーン環境で導入できる。
- [ ] Typer CLIが日本語ヘルプを表示する。
- [ ] SQLite schemaとAlembic migrationがある。
- [ ] 秘密情報、個人パス、DB、生成物が適切にGit除外される。
- [ ] formatter、lint、型検査、pytestの実行方法が文書化されている。

## 3. 案件作成

- [ ] 分析対象者、期間、媒体、重点対象、基準日を入力できる。
- [ ] 対象者IDと案件IDが重複なく再現可能に発行される。
- [ ] 指定Vaultまたはテスト用ルートへ仕様どおりのフォルダが作成される。
- [ ] `request.yaml` と初期状態ファイルが生成される。
- [ ] 同じ対象者の複数案件と期間重複を許容する。

## 4. 原文保全

- [ ] raw原文が加工処理で上書きされない。
- [ ] SHA-256等の内容ハッシュを保存する。
- [ ] 同じ原文を再取込みしても二重登録・二重処理されない。
- [ ] 出所、媒体、発言日時、公開日時、取得日時を分離できる。
- [ ] processed、予想、評価からrawと原文位置へ追跡できる。

## 5. AI入出力

- [ ] 固定JSON SchemaとPydanticモデルがある。
- [ ] Schema不適合を人間に分かる日本語で報告する。
- [ ] 存在しないID参照を拒否する。
- [ ] 原文に存在しない引用を拒否または要確認にする。
- [ ] 同じAI出力の再取込みが冪等である。
- [ ] AI出力を検証前に正式テーブルへ登録しない。
- [ ] 判断不能、低確信度、評価不能を許容する。

## 6. 市場データと最小評価

- [ ] provider interfaceでyfinance、FRED、CSVを分離できる。
- [ ] unit testはネットワークなしで再現できる。
- [ ] 実ネットワーク検査はintegration testへ分離される。
- [ ] 取得元、ティッカー、通貨、期間、取得日時、調整方式を保存する。
- [ ] 欠損・休場日・重複データを検査する。
- [ ] 取得不能な価格を推測しない。
- [ ] 上昇・下落の方向と実際の変化率をfixtureで正しく計算する。
- [ ] 評価基準日を変更しても履歴またはスナップショットを保持できる。

## 7. 次行動案内

- [ ] ターミナルに推奨行動を一つ表示する。
- [ ] 理由、担当 `[PYTHON]`／`[AI Cursor]`／`[AI ChatGPT]`／`[USER]`、入力、出力を表示する。
- [ ] 最大2件程度の代替案とブロッカーを表示する。
- [ ] `status.yaml`、`WORKFLOW_STATE.json`、`NEXT_ACTIONS.md`、`OPEN_ISSUES.md` を生成する。
- [ ] Pythonが生成した状態を正本とし、Cursorが存在しない成果物を完了扱いしない。
- [ ] 中断後に同じ案件から再開できる。

## 8. 仕様上の重要な回帰確認

- [ ] 同じ予想の後日の再表明を別表明として保持できる。
- [ ] 再表明を同じ予想系列へ関連付けられる。
- [ ] 複合予想の構成要素が予想件数を水増ししない。
- [ ] 過去実績と現在予想を別収集せず、状態で分類できる。
- [ ] 明示期限とAI推定期限とシステム既定期限を混同しない。
- [ ] 条件不成立を不的中にしない。
- [ ] 想定より早い実現を正式判定と別に記録できる。
- [ ] テーマ・業種の対象解決後、市場結果に合わせてマッピングを書き換えない。

## 9. 文書と監査

- [ ] 実装計画、進捗、暫定判断が更新されている。
- [ ] 各結果から入力、処理バージョン、AIモデル、プロンプト、市場データへ追跡できる設計である。
- [ ] エラーに原因、影響、次の操作が表示される。
- [ ] READMEまたは開発者向け手順でセットアップ、テスト、代表コマンドが分かる。
- [ ] 仕様変更は決定履歴へ反映される。

## 10. MVP外として誤って先行実装しないもの

- [ ] 完全自動の全媒体収集をMVP必須にしていない。
- [ ] 複数アナリストの高度な総合ランキングを先に作っていない。
- [ ] 総合点一つだけで評価する設計にしていない。
- [ ] 3D可視化や豪華なGUIを優先していない。
- [ ] 大規模なループエンジニアリング基盤を導入していない。
